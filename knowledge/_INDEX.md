## Gotchas
Debugging discoveries, bug resolutions, lessons learned — things that cost time once and shouldn't cost time twice.
- [[Gotchas/2026-08-11 - Sentinel feed fabricated a CE direction on signals that had none]] — **Rule 2 class, read before touching `SafetyCard.tsx`, `extractSafetyFeed` or `sideInFocus`.** Four stacked defects made the feed claim Sentinel favoured *calls* on evidence that said the opposite: the CE/PE badge was recovered by substring-matching card prose and **defaulted to "CE CALL"** for anything not matched as PE (a bearish CPR breakdown got a bullish badge; "O**PE**N range" got PE PUT); a *neutral* bias was coerced to bullish, manufacturing a side out of the one case that should surface nothing; the four-condition `publication` gate was taken as a parameter and **never referenced**, silently reverting a documented decision while its long explanatory comment still sat above the body; and "progress" measured `spot − nearest ATM strike`, a rounding artifact bounded by half a strike step, so on NIFTY it could never leave ±25 and "invalidated" was unreachable. Records why one `ActionLabel` reached by two sources (a real directional read vs. a bare `ACTION_MAP` detection) is the root confusion, why the anchor keys by symbol alone rather than `(symbol, side)`, why progress must be measured *in the surfaced side's favour* or a PE card reads "market up 5" while winning, and why the badge rule had to move out of JSX to be testable at all. **A doc comment is not a gate** — and two harness tests were already failing on the branch, which is how the revert stayed invisible
- [[Gotchas/2026-07-23 - Sentinel not working was four stacked config+build faults]] — "Sentinel only shows simulated data" was **four stacked faults**: service stopped (→ web `DEMO` fallback), `SENTINEL_SERVICE_TOKEN` held an `nvapi-` value (401), `MARKET_DATA_FEED=Live` silently means simulated (only `dhan`/`simulated` are valid), and `getCandles` hardwired to the simulator. Plus the `dist/src` vs `dist` stale-`main.js` build-layout trap and the `.tsbuildinfo` cache that masks `tsconfig` changes
- `packages/database/prisma/seed.ts`'s `seedDemoAccount()` throws `bcrypt.hash is not a function` — a pre-existing ts-node ESM/CJS interop bug, confirmed unrelated to any recent change via git diff, not yet fixed. See [[Patterns/2026-07-18 - Market Data Migration 1 executed (Quote revision, baseline established)]].
- No ESLint config exists anywhere in the repo (pre-existing, not caused by any specific change) — confirmed during Market Data Migration 1.
- `prisma migrate dev` refuses to run in a non-interactive/non-TTY shell, even with `--create-only` — hand-author migration SQL from `prisma migrate diff --script` output and apply with `prisma migrate deploy` instead. See [[Patterns/2026-07-18 - Market Data Migration 1 executed (Quote revision, baseline established)]].
- Always diff a proposed Prisma migration against the **live DB** (`prisma migrate diff --from-url`), not just the schema file — schema.prisma can be edited ahead of any migration during a design conversation, silently drifting from what's actually applied.
- Zustand stores with `persist` middleware need `skipHydration: true` + a manual `rehydrate()` in `useEffect` (deterministic seed data, no `Math.random()`/`Date.now()` before rehydration) to avoid SSR/client hydration mismatches. See [[Patterns/2026-07-18 - M3 dockable workspace (zustand store, dock engine, command palette)]].
- Setting `NVIDIA_NIM_BASE_URL` without `NVIDIA_NIM_API_KEY` registers the `nvidia-nim` provider successfully and then 401s on every call ("Header of type `authorization` was missing") — the base URL alone is enough to register because self-hosted NIM needs no key. Run `npm run nim:smoke` in `services/sentinel` to catch it up front. See [[API/2026-07-23 - NVIDIA free tools (NIM API, Agent Skills)]].
- NIM free-tier latency is **not predicted by parameter count** and the catalog never shows it — the *smallest* model tested (`meta/llama-3.2-3b-instruct`) was the slowest and the only outright failure: 2 of 4 prose calls timed out at 90s and it never answered a tool call (240s, 0 bytes), while `meta/llama-3.1-8b-instruct` answers in 0.3s and tool-calls reliably. Always time **and** tool-test a model before pinning it to a tier, especially `fast` — that is where every Sentinel agent, the orchestrator, the brain and `NewsEventClassifier` run. Same note.
- NIM reasoning models return chain-of-thought in `message.reasoning`, not `content`, and spend `max_tokens` on it before writing any visible text — a 60-token budget with `enable_thinking: true` returns a truncated answer. NIM also 400s on `response_format: {type:'json_object'}` (vLLM wants a schema). Same note.
- A mount-only `useEffect` (e.g. in `AppFrame`) does not re-run on client-side route navigation — if "the action succeeded but the shell/UI didn't update," suspect a mount-only effect on a component that doesn't remount on navigation. See [[Patterns/2026-07-18 - M4 Step1 real auth session (sessionStore, AppFrame remount gotcha)]].

## API
API integration notes — auth quirks, rate limits, payload shapes, gotchas specific to a third-party API.
- [[API/2026-08-11 - Dhan Algo Strategies]] — **read before automating any order placement against Dhan.** The headline: **Dhan has no endpoint that returns algo strategies** — `algos.dhan.co` is a UI-only marketplace of third-party, exchange-approved algos with no API. What exists is one server-side rule engine (**Conditional Triggers**, `/v2/alerts/orders`, API v2.5) whose entire expressible strategy space is the cross-product of 21 fixed-period indicators × 9 operators × 4 timeframes — catalogued here as 14 named archetypes — plus the Tier-3 primitives (`/orders`, `/super/orders`, `/forever/orders`). Records the walls that decide architecture: **Conditional Triggers exclude F&O entirely** (equities/indices only), **one comparison per trigger — no AND/OR**, `frequency: ONCE`, and `trailingJump: 0` silently *cancels* a Super Order's trail. **Static IP whitelisting is mandatory for every order API** (SEBI algo regulation, v2.4) with a 7-day change lock — an infra constraint that cannot be resolved at deploy time; tokens expire in 24h. Also: `algoId` is read-only Dhan attribution, not a strategy id you supply; the docs' lookback limits are more generous than this repo's measured behaviour; and two doc self-contradictions (`comparisonType` enum, a claimed "Exit All API" that no page documents). Reference implementation: `scripts/dhan_algo_strategies.py`
