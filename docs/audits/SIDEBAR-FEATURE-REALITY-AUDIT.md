# TradeW — Sidebar Feature Reality Audit

**Date:** 2026-08-23
**Scope:** Every item reachable from the `apps/web` sidebar, traced Sidebar → Route → Page → Hook → API → Service → DB/External → UI.
**Method:** Static trace **plus** live execution. A local PostgreSQL 16 + pgvector cluster was created, all 40+ Prisma migrations applied, the database seeded, and four processes booted: `services/api` (:4000), `services/sentinel` (:4010), `services/sentinel-py` (:4011) and `apps/web` (:3000). Every sidebar route was then loaded in headless Chromium under a real authenticated session, and ~60 API endpoints were exercised with curl.

> **Environment caveat, stated once and applied throughout.** This sandbox's egress proxy blocks all outbound HTTPS except a package-registry allowlist. Dhan, NSE, Binance, Twelve Data and the newswires are therefore unreachable **here**. Every finding about those integrations is marked `NOT VERIFIED — blocked by sandbox egress` and reasoned from code. Their failure in this environment is **not** evidence of an application defect — and in fact the app's error handling for exactly this case turned out to be the most rigorously built part of the product.

---

## 1. Executive summary

TradeW is a substantially real application, not a mockup. The paper-trading OMS, authentication, entitlements, settings, notifications, learning, discipline limits and the Sentinel intelligence stack are genuine end-to-end systems backed by a 2,290-line Prisma schema, 40+ applied migrations and 1,560 passing unit tests. Both `apps/web` and `services/api` typecheck clean. Server-side authorization is real and correctly enforced.

The application's defining characteristic is an unusually disciplined **"never fabricate data"** policy, visible in code comments and — more importantly — verified at runtime. With the market-data bridge down, the Trade page renders *"Market data API not connected … no simulated series will be drawn in the meantime"*; `POST /sentinel/observe` returns `503 "Sentinel does not substitute simulated data"`; Crypto and Forex say *"nothing is shown rather than a stale price."* That is rare and it is worth protecting.

Three things break that policy, and they are the report's headline findings:

1. **`/research` is a fabricated financial-analysis page.** It renders an "🤖 TradeW AI Summary" with *Overall Outlook: Bullish, Confidence 87%, Business Quality 9.2/10, Financial Health 8.8/10, Risk: Medium* — all hardcoded JSX, generated by nothing. P/E, ROE, EPS, market cap, shareholding percentages and a bar chart are static constants shown for **every** symbol. The price falls back to `symbol === 'RELIANCE' ? 2945.20 : 1500.00` with no "stale" marker. Two different market-cap figures appear on the same screen (₹19,73,284 Cr vs ₹19,81,568 Cr), which is itself proof both are invented. Nine sub-tabs (Fundamentals, Peers, Risk Factors…) change nothing but a highlight colour, and four action buttons have no `onClick` at all.
2. **The PAPER / LIVE toggle in the top bar is a lie by omission.** `TopBar.tsx:25` holds it in local `useState` that nothing reads. Clicking **LIVE** turns the pill green and labels the session live; orders still go to the paper OMS. In a trading product this is the single most dangerous fake control in the app.
3. **The Home dashboard's index cards, hero card and ticker silently fall back to hardcoded prices.** Verified at runtime: with the bridge down the dashboard showed NIFTY 23,882.15 (+0.54%), BANKNIFTY 56,742.30, SENSEX 78,250.60 — the exact literals in `lib/mock/market.ts:62-68` — with no staleness indicator on the cards. The Markets page does the same with a 21-Jul-2026 CSV snapshot of 139 indices. The chart beside them correctly refuses to draw. The same screen is therefore simultaneously honest and dishonest.

Beyond that, the app has **one structural dependency that gates a third of the sidebar**: the Dhan live-feed bridge (`services/market-data/scripts/live-feed-server.ts`, port 4600). It requires a valid broker token *and* a successful download of Dhan's scrip master to boot at all — it `process.exit(1)`s otherwise. The paper OMS prices **exclusively** from this bridge (`market-price.service.ts:252`); it never falls back to the seeded `Quote` table. **With the bridge down, no order can be placed** — verified: `POST /sim/orders` returned `404 "Market data is temporarily unavailable"`.

**Verdict:** the platform's spine is production-grade. Its periphery contains one page that should be taken down or rebuilt before any real user sees it, one control that should be disabled today, and a documentation set that has drifted badly out of date.

## 4. Feature-by-feature audit

### 4.1 Home — `/dashboard` — 🟡 PARTIALLY WORKING

**Intended:** the market command centre — "what is happening right now."

**Actual:** `MarketWorkspace` composes nine widgets. Split by data source:

| Widget | Source | Real? |
|---|---|---|
| `DashboardHero` | `useDhanLiveFeed` → mock `INDEX_QUOTES` fallback | live-or-fake, unlabelled |
| `IndexOverview` | same | live-or-fake, unlabelled |
| `MarketOverview` (chart) | `useCandles` → bridge `/candles` | **real or explicitly empty** |
| `MarketMovers` | ranks live universe; falls back to `TOP_GAINERS/LOSERS` | live-or-fake |
| `SectorHeatmap` | averages live constituents; falls back to `SECTORS` | live-or-fake |
| `TodaysTrades` | `/sim/trade-history` | **real** |
| `WatchlistWidget` | static `WATCHLIST`, live LTP overlay | **fixed list — no backend** |
| `RiskAlerts` | `RISK_ALERTS` constant | **fully mock** |
| `MarketNews` | `useNews` → `/news` | **real** |

**Why the working parts work:** `TodaysTrades` → `useQuery` → `fetchTradeHistory()` → `GET /sim/trade-history?from=&to=` → `TradeHistoryService` → Prisma `Trade` → Postgres → table + footer that sums exactly the rows displayed. Verified: `200 {"rows":[],"total":0}` on a fresh account, correct empty state in the browser.

**Why the rest doesn't:** `useDhanLiveFeed` polls `/feed/quotes`, proxied by `next.config.js` to `127.0.0.1:4600`. When that returns non-200 the hook settles on `status: 'unreachable'` after a 20 s grace window, and each widget silently substitutes its mock constant. **Runtime proof:** the dashboard rendered NIFTY 23,882.15 / +128.40 / +0.54 % — byte-identical to `lib/mock/market.ts:63` — with no visual distinction from a live quote.

**What is fake:** `RISK_ALERTS` (never live by design); `WATCHLIST` membership; every sparkline (`spark()` is a deterministic sine wave); the fallback index/mover/sector numbers.

**Missing:** a `Watchlist` model and CRUD endpoints (the "Manage" and "Add Symbol" buttons are correctly `disabled` with honest tooltips); a real alerts feed; a staleness badge on fallback quotes.

**In production:** works well **if** the bridge runs. If it doesn't, the page shows month-old prices as current while the chart beside them admits it has no data.

### 4.2 Markets — `/markets` — 🟡 PARTIALLY WORKING

Four tabs over `useDhanLiveFeed`. Indices = 139 rows from `MW-All-Indices-21-Jul-2026.csv` (`lib/mock/indices.ts` — real but **dated** figures), live-overlaid for the 4 symbols the bridge covers. Stocks = ~210 F&O symbols, price `null` until live. ETFs = bridge-only, empty otherwise. Commodities = mock with live overlay.

Rows carry a teal `●` when genuinely live, and the card header shows a `LIVE`/`CLOSED` badge — but `LiveBadge` returns `null` for `loading` and `unreachable`, so a stale table gets **no badge at all**. Runtime proof: with the bridge down the page rendered NIFTY 50 at 24,191.45 with 52-week highs and 30D/365D percentages and nothing indicating the data is a month old.

Buy / Sell / Chart row actions are real — they route to `/trade?symbol=…&action=buy|sell`.

**Fix:** render `LiveBadge` as `STALE — as of 21 Jul 2026` when `status === 'unreachable'`, and null out `ltp` for indices exactly as the Stocks tab already does.

### 4.3 Portfolio / Orders / Positions — `/portfolio`, `/orders`, `/positions` — 🟢 FULLY WORKING

One component, three entry points (`PortfolioClient({ initialSection })`) — no duplicated tables.

**Flow:** `PortfolioClient` → `usePortfolioSummary/usePositions/useHoldings` (TanStack Query, 5 s cadence, paused when hidden) → `GET /sim/portfolio | /sim/positions | /sim/holdings` → `AuthGuard` → `PortfolioService` / `PositionService` / `HoldingsService` → Prisma → Postgres.

**Verified live:** `/sim/portfolio` → `{"startingBalance":1000000,"availableBalance":1000000,…,"availableMargin":1000000}`; the browser rendered *AVAILABLE BALANCE ₹10,00,000.00 … AVAILABLE MARGIN ₹10,00,000.00* and correct empty states for Orders and Positions.

**Writes are real and wired:** exit position (`POST /sim/positions/:id/exit`), exit-all, convert with preview (`GET/POST …/convert`), modify order (`PATCH /sim/orders/:id`), cancel (`DELETE /sim/orders/:id`), sell holding (`POST /sim/holdings/:id/sell`). Performance section reads six distinct real endpoints.

**Error handling is notably good:** a failed poll with cached data on screen does *not* raise a banner — the failure surfaces only when there is genuinely nothing to show (`PortfolioClient.tsx:70-78`).

**Caveat inherited from §4.4:** positions can only ever be non-empty if orders can fill, which requires the bridge.

### 4.4 Trade — `/trade` — 🔵 BLOCKED BY INFRASTRUCTURE

Genuinely built: instrument header, TradingView charts, option chain, technicals, depth, order ticket, blotter, Sentinel panel, strategy overlay. `OrdersPanel` submits through `placeOrderWithDiscipline()`, which translates a `409 discipline_limit` into a typed `DisciplineBreachError` and raises the `FrictionPrompt` — a real, tested safety mechanism.

**Root cause of the block, precisely:** `SimController.create` → `OrderService` → `MarketPriceService.getPrice()` (`services/api/src/sim/market-price.service.ts:252`), which calls `getSnapshot()` against `DHAN_LIVE_URL` (default `http://localhost:4600`) and, for options, `GET /optionchain`. On failure it throws `NotFoundException('Market data is temporarily unavailable — try again shortly')`. **There is no fallback to the seeded `Quote` table.** Verified: `POST /sim/orders {"symbol":"NIFTY26JUL24800CE","side":"BUY","type":"MARKET","productType":"MIS","quantity":75}` → `404 "Market data is temporarily unavailable"`, and positions stayed `[]`.

The bridge itself cannot start without a Dhan credential — `live-feed-server.ts:520-526` logs and `process.exit(1)`. It also needs Dhan's scrip master at boot (HTTP 403 here).

**The page is exemplary about it.** Runtime text: *"Market data API not connected — The Dhan live-feed bridge (port 4600) is not reachable, so no real candles could be loaded. Start it and reload — no simulated series will be drawn in the meantime."*

**Validation is real:** a malformed order body returned `400 ["symbol must be a string","productType must be one of the following values: MIS, CNC, NRML"]`.

**In production:** works if `live-feed` runs with a valid rotating Dhan token; fails closed and legibly otherwise. `infra/docker/docker-compose.prod.yml:177` does define the `live-feed` service (contrary to `docs/APPLICATION-STATUS.md`, which still calls this an undeployed gap).

### 4.5 AI Sentinel — `/sentinel` — 🟡 PARTIALLY WORKING (premium)

Three real backends: `services/sentinel` (:4010 — observation pipeline, brain, ontology, corpus), `services/sentinel-py` (:4011 — user strategy parser and watcher), and `sentinel.service.ts` DB-backed routes.

**Entitlement gating is genuine and server-side.** Non-entitled account → `403 {"message":"Missing entitlement: sentinel","capability":"sentinel","reason":"no_subscription"}` on `/sentinel/observations`, `/sentinel/strategies`, `/sentinel/journal`, `/sentinel-intelligence/status` **and** the `/sentinel-py/*` proxy. Calling the API directly does not bypass it. The page itself renders `SentinelPricingView` instead of the workspace, and does so only after the session resolves — avoiding a one-frame flash of the paywall to paying subscribers.

**Verified working with the services up:**
- `GET /sentinel/strategies` → 8 built-in strategies with rules and invalidations.
- `GET /sentinel/strategies/registry` → 5 exposed strategies with purposes.
- `GET /sentinel-intelligence/status` → `{"corpus":{"documents":242,"chunks":2334,"concepts":66}}` — a real indexed corpus.
- `POST /sentinel-py/strategies/parse` → real deterministic parse. *"Mark the first 15 minute opening range. Go long above the high after a retest. Stop loss below the low. Target 1:2."* produced `timeframe: "15m"`, `levels: ["15m_high","15m_low"]`, a mandatory `retest` rule, `entry.long: "price_above_15m_high"`, `stopLoss: "15m_low"`, `targets: ["1R","2R"]`.
- `GET /sentinel/journal`, `POST /sentinel/journal`, `GET /sentinel/session-summary` — all real Postgres round-trips.

**What is NOT working:**
- **The core observation cannot run without market data.** `POST /sentinel/observe` → `503 "No real market data available for NIFTY (15m candles). Live feed: not configured (SENTINEL_LIVE_FEED_URL is unset). Stored history: no 15m rows backfilled for NIFTY. Sentinel does not substitute simulated data."* Exactly the right behaviour, and a hard block on the feature.
- **Service-token strength gate:** `services/sentinel/src/app.controller.ts:46` rejects any `SERVICE_TOKEN` under 24 characters or on a weak-value list. A short token yields `502 "Sentinel service error: 401"` from the API with no hint of the cause — a real operability trap I hit myself.
- **The strategy parser is a narrow keyword grammar, not an LLM.** *"Buy NIFTY when price closes above the 20 EMA … and RSI is above 60"* parsed to zero rules, warning *"Not understood, so not watched for: 'buy','nifty','closes','ema','chart','rsi'."* Honest, but a user typing indicator language gets nothing.
- **The journal has no UI.** `useSentinel` fetches `/sentinel/journal?limit=10` and exposes an `addJournal` mutation, but the only renderer — `components/sentinel/TradingJournal.tsx` — is **never imported**. The write endpoint works and is unreachable from the product.

**Runtime render:** the workspace degrades correctly — a *"Sentinel reconnecting… Sentinel answered HTTP 503"* banner over a live shell showing `MARKET REGIME AWAITING`, `SENTINEL CONFIDENCE —`, `STATE MACHINE OFFLINE`. No invented numbers.

### 4.8 Research — `/research` — 🟠 MOCK / PLACEHOLDER *(most serious finding)*

**What exists:** a polished single-file page (`app/(workspace)/research/page.tsx`, 339 lines).

**What is real:** the symbol picker, the price header **when the bridge is up** (`useDhanLiveFeed`), and the price chart (`useCandles`).

**What is fabricated — verified in the browser:**
- *"🤖 TradeW AI Summary · Generated by TradeW AI — Overall Outlook **Bullish** 🐂 · Confidence **87%** · Business Quality **9.2/10** Excellent · Financial Health **8.8/10** Very Good · Valuation **Slightly Expensive** · Risk **Medium** · Momentum **Strong**"* — hardcoded JSX. No model, no service, no data. Attributing invented investment conclusions to an AI is the most consequential defect in this repository.
- Key Metrics — Market Cap, P/E 24.62, P/B 2.12, ROE 14.28 %, ROCE 17.62 %, EPS ₹119.61, Dividend Yield 0.34 %, D/E 0.15, Current Ratio 1.52 — static, identical for every symbol.
- "Financial Performance" chart — four `<div>`s with fixed Tailwind heights (`h-20 h-24 h-28 h-32`). Not a chart.
- Shareholding — Promoters 50.13 % / FIIs 24.71 % / DIIs 15.36 %, static.
- Analyst target ₹2,820.00 vs current ₹2,945.20, static.
- **Internal contradiction proving fabrication:** header market cap ₹19,73,284 Cr, Key Metrics market cap ₹19,81,568 Cr — on the same screen.
- **Price fallback:** `const price = liveStock?.ltp ?? (symbol === 'RELIANCE' ? 2945.20 : 1500.00)` and `changePct ?? 1.45` (`page.tsx:32-33`). Every unknown symbol shows ₹1,500.00 +1.45 % as though real.
- **Nine dead tabs:** `activeTab` is referenced in exactly two places — the `useState` and the button's highlight class. Clicking *Fundamentals*, *Peers* or *Risk Factors* changes nothing.
- **Four dead buttons:** `+ Watchlist`, `Compare`, `Export PDF`, `Share` have no `onClick` (`page.tsx:67-70`).

**Documentation contradiction:** `docs/APPLICATION-STATUS.md:108` states *"The `/research` page is a deliberate 'coming soon' placeholder."* It is not; it is a fully-dressed page presenting invented analysis as fact.

**Recommendation (P0):** replace with `NotBuiltYet` — the component already used by `/backtesting` and `/community` — until a real fundamentals provider is integrated. This is a ~30-minute change that removes the repository's largest liability.

### 4.11 Alerts — `/notifications` — 🟡 PARTIALLY WORKING

**Real read path:** `NotificationsClient` → `useNotifications` → `GET /notifications` → Prisma → Postgres. Mark-read and mark-all-read (`PATCH :id/read`, `PATCH read-all`) are real and optimistic. The bell drawer, the badge and this page share one store slice via `NotificationSync` (the "two sources of truth" defect described in the status doc has been fixed since).

**The real problem — there is almost nothing to read.** A repo-wide search finds exactly **one** producer of `Notification` rows: `discipline.service.ts:380`, which fires once when a trader hits a self-set profit target. Order fills, rejects, Sentinel observations, learning milestones and broker events write nothing. For virtually every user this feed is permanently *"You're all caught up."*

**And `POST /notifications` is broken for every possible body.** `CreateNotificationDto` (`notification.controller.ts:9-18`) carries `@ApiProperty()` but **no `class-validator` decorators**, while `main.ts:148` applies `new ValidationPipe({ whitelist: true })`. Whitelisting strips every undecorated property, so the service receives `{title: undefined, body: undefined, category: undefined}` and Prisma throws. Verified: a correctly-shaped body returned `500 Internal server error` with `Argument 'category' is missing` in the log. No frontend calls it, so it is a broken orphan rather than a live outage.

## 9. Authentication & authorization audit

**Authentication is real.** JWT bearer + rotating single-use refresh tokens; 15-minute access TTL (observed by expiry mid-audit); bcrypt passwords; session records with revoke-others; Google OAuth and phone OTP present but disabled without config (`/auth/methods` → `{"password":true,"google":false,"phone":false}`); `JWT_SECRET` fails fast at boot via a dedicated secret guard.

**The middleware gate is routing only — and says so.** `apps/web/src/middleware.ts` reads a valueless `tw_auth` cookie because middleware cannot read `localStorage`. The file documents at length that forging it yields an empty shell whose every API call 401s. Verified: without the cookie all 23 routes returned `307`; with a forged cookie all returned `200` and every data call 401'd.

**Authorization is enforced server-side.** Verified with a fresh non-entitled token: `403 Missing entitlement: sentinel` on `/sentinel/*`, `/sentinel-intelligence/*` **and** the `/sentinel-py/*` proxy. Learning correctly returns free courses with `hasPro:false`. No frontend-only gate was found on any premium surface.

**Admin and control planes are separately gated.** `/admin/*` → `401 "Admin portal disabled (ADMIN_API_TOKEN not configured)"`; `/control/*` → `401 "Control request rejected"` (Ed25519 signature over the raw request bytes, with `rawBody: true` configured for exactly that reason). The admin console is a separate app with its own session cookie.

**Other hardening actually present:** `whitelist: true` validation, `@nestjs/throttler` with `Retry-After`, loopback-by-default binding, an enforced CSP with documented `unsafe-inline` limits, HSTS in production only, and a service-token strength floor.

**Gaps:** the `x-service-token` scheme is a shared static secret with no rotation; a weak token produces an opaque `502`; the two undecorated DTOs (§4.11) turn malformed input into `500`s.

## 17. The bottom line

> **"If I click every item in the sidebar right now, what will actually happen?"**

Every one of the 19 items navigates. Nothing 404s, nothing throws, no error boundary fires — verified in a real browser across all 19 routes.

**Seven work properly.** Portfolio, Orders and Positions show your real paper account from Postgres (₹10,00,000 starting balance, real empty states) and their buttons — exit, convert, modify, cancel — genuinely execute. Settings saves to the server and the saved values actually change the app. Profile is real. Learning shows courses generated from an indexed 243-document corpus with real progress tracking. Reports exports genuine CSVs of your own records.

**Four are honest about being empty.** Backtesting and Community say plainly that nothing is built and point you somewhere useful. Crypto and Forex say *"nothing is shown rather than a stale price."* Calendar names the exact NSE failure.

**Trade is the biggest disappointment, and it is infrastructure, not code.** The workspace is fully built, but with the Dhan bridge down you get *"Market data API not connected … no simulated series will be drawn"* — and **you cannot place a single order**, because the OMS prices only from that bridge and has no fallback.

**AI Sentinel needs a subscription (genuinely enforced, not a frontend trick) and two extra services.** Your strategies, the 5-strategy registry and the 2,334-chunk knowledge corpus are real; the live observation returns `503` and refuses to invent a reading.

**Three things will lie to you.**

1. **Research** is the worst. It shows *"🤖 TradeW AI Summary — Bullish, Confidence 87%, Business Quality 9.2/10, Risk Medium"* generated by nothing at all, alongside P/E, ROE, EPS, shareholding percentages and a fake bar chart that are identical for every stock. It prints two different market-cap figures on the same screen. Nine tabs change only a highlight colour. Four buttons have no handler.
2. **Home, Markets and the ticker** silently swap in hardcoded prices when the feed is down — NIFTY 23,882.15 +0.54 %, and 139 index rows from a 21-July-2026 CSV — with no staleness marker. The chart beside them correctly refuses to draw, which is what makes the contrast so stark.
3. **The PAPER/LIVE toggle** turns green and says LIVE when clicked, and does nothing whatsoever.

**Alerts will always look broken and isn't.** The feed is real and correct; only one event in the entire codebase ever writes to it.

**Why:** this codebase has a strong, deliberate "never fabricate data" culture — visible in the error text, in the disabled buttons with honest tooltips, in `POST /sentinel/observe` refusing to simulate. Two pages (`/research`, the News rail) and two controls (the LIVE toggle, the unmarked quote fallbacks) predate or ignore that rule. Fixing them is a few hours of work, and it is the difference between a platform that is trustworthy and one that merely looks finished.
